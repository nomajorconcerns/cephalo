Command parsing, not just text matching

Rules also see the parts of a command, not only its text.

How it works: The command is split at pipes, &&, ||, ;, subshells and $(...). Inline code such as bash -c, python -c, node -e, powershell -Command and cmd /c is opened up. Each part is checked, and so is the original text, so parsing can only add blocks.

Limit: it reads the command as written. A script file, or a command assembled at run time, is still out of sight.

Coming Nov 10 in 0.2.0Free

Bypass fixes

Closes the gaps found in 0.1.1.

How it works: Grep, Glob, WebFetch and WebSearch calls now go through the hook. Relative paths and symlinks are resolved before a path rule is checked. Shell writes to the Claude Code and Hermes config, and to Cephalo’s own install folder, are blocked.

Limit: these are still rules. Anything running as you outside the hooks can edit those files.

Coming Nov 10 in 0.2.0Free

Self-integrity check

Warns if Cephalo has been switched off or edited.

How it works: The build records a SHA-256 hash of every installed file. At the first call of a session, and in cephalo doctor, Cephalo checks that its hook is still in the agent’s config and that the files match, and warns loudly if not.

Limit: it detects a change; it cannot stop one. Someone who edits both the files and the recorded hashes as the same user can hide it.

Coming Nov 10 in 0.2.0Free

Optional fail-closed mode

Off by default. When on, a broken hook blocks instead of letting the call through.

How it works: cephalo config set fail-closed on. If the hook crashes, runs past hook-timeout (8 seconds by default), or gets input it cannot read, the call is blocked and the reason is logged.

Limit: a broken hook then stops your agent’s tool calls until you fix it. That is the trade-off, and why it is off by default.

Coming Nov 10 in 0.2.0Free

Allow and ask rules

A rule can be an exception, or put the call to you.

How it works: Add action: allow to make an exception (the first matching rule still wins), or action: ask to have you approve or deny. An allow rule cannot lift Cephalo’s own protections. Where the agent cannot ask, the ask-default setting decides, and the log says so.

Limit: only Claude Code can show an approval prompt. For Hermes, Codex and Cursor, ask falls back to your default.

Coming Nov 10 in 0.2.0Free

Shadow mode

Try a rule on real traffic before you trust it.

How it works: Add shadow: true to a rule, or run cephalo config set shadow on for all of them. A shadow rule logs what it would have done and lets the call through. cephalo log --shadow lists those calls. Cephalo’s own protections stay on.

Limit: nothing is stopped while a rule is in shadow mode. It is for testing a rule, not for protection.

Coming Nov 10 in 0.2.0Free

Themed CLI

Five colour schemes: reef, abyss, coral, glow and ink.

How it works: cephalo theme list shows them, cephalo theme set glow saves one, CEPHALO_THEME=glow is for one run. Each has a dark and a light palette. ALLOW, BLOCK and ASK always keep their words, so meaning never depends on colour alone.

Limit: colour is cosmetic. It falls back to 256, 16 or no colour, and is off for pipes and NO_COLOR. Hook output is never coloured.

Coming Nov 10 in 0.2.0Free

Animated octopus

The octopus waves its tentacles while slow commands run.

How it works: While doctor, mcp scan, models eval, replay, cost and similar commands work, a six-line octopus waves beside a status message, in your theme’s colours. It clears itself before the results print.

Limit: only on an interactive terminal. Never in hook output, in CI, with NO_COLOR, with CEPHALO_NO_ANIMATION=1 or when reduced motion is requested. Then you get a plain “Working...” line.

Network egress allowlist

Agents can only reach the domains you list.

How it works: You keep a list in ~/.cephalo/egress.yml. Shell commands (curl, wget, Invoke-WebRequest, ssh and the like), WebFetch and MCP calls are checked against it. Others are blocked, or put to you in ask mode. Your own machine (loopback) is always allowed.

Limit: it matches the destinations it can see in the call. A program that opens its own connections inside a script is not seen.

Coming Nov 10 in 0.2.0Pro and Team

Tamper-evident audit log

Shows whether the audit log was edited.

How it works: Each line carries a sequence number, the hash of the line before it, and its own hash. cephalo audit verify reports lines that were edited, removed, reordered, inserted or cut off the end. cephalo audit head prints a value to keep somewhere else.

Limit: it shows tampering; it does not prevent it. Someone who rewrites the whole chain can produce a log that verifies, unless you keep a copy of the latest hash elsewhere.

Coming Nov 10 in 0.2.0Pro and Team

Bypass benchmark

Measures how many known bypasses your rules stop.

How it works: cephalo bench runs about 100 known bypass attempts and ordinary commands through your rules, without running any of them. It reports the block rate, what got through, and any ordinary command blocked by mistake. A CI job runs it on Windows, macOS and Linux.

Limit: it measures only the bypasses it contains. A high score is not a guarantee against the next one.

How it works

      
Four steps, in this order, every time.

1. The agent asks to use a tool

          
Before every tool call, Claude Code and Hermes run Cephalo's hook and send it the call as JSON: the tool name and its input.

          

        

        

          
2. Cephalo cleans it up

          
Shells let you disguise a command: empty quotes, carets, backticks, .. in paths. Cephalo removes them for your operating system, then checks both the raw and the cleaned text.

          

        

        

          
3. Rules are checked in order

          
Your rules come first, then the built-in rules for your system. The first one that matches decides. The rest are not needed, which is why rule order matters.

          

        

        

          
4. Decision

          
A block goes back to the agent as a refusal and the tool call never runs. Either way, one line is added to the audit log.

      What it can do
      
      
      A small CLI that is easy to check.
      
      
      Choose a command to replay it. Output for rules, test, mcp, tripwire, vault, replay and incident was captured from real runs on throwaway data (paths shortened, a few lines trimmed). doctor shows a healthy, fully installed machine using the real line formats. log, watch and init are representative.
      
    
      
    
      
      
      
      
      
        
      
          
      
          
      
        
      
        
      
      
      
    
      
    
      
      
      cephalo rules show <id> prints one rule in full, including its pattern, and the default it was changed from.
      
      
      cephalo rules reset [--yes] backs up rules.yml, then rewrites it from the built-in defaults. Nothing is deleted.
      
      
      cephalo install / uninstall claude|hermes are idempotent, parse configs strictly, refuse invalid ones, and back up before writing. Uninstall removes only Cephalo's own entries.
      
      
      cephalo hook claude|hermes|codex|cursor is the entry point the agents call. It prints pure JSON only, and fails open if anything breaks. The Codex and Cursor adapters are unit-tested against the vendors’ documented formats but have not run inside the real apps, and init does not install them.

      BuiltFree · since 0.1.1
      
        
      Everything in version 0.1.1
      
        
      All of this is in the published 0.1.1 release, is MIT licensed, and stays free and open source. Each entry says what it cannot do.
      
        
      
        
      
        
      MCP firewall
      
        
      MCP servers are identified by what they run or where they live, not by the name in a config file. An unknown server is logged (audit mode) or blocked (enforce mode). cephalo mcp allow approves one.
      
        
      Limit: the runtime proxy handles local stdio servers only. Remote URL servers are covered by the allowlist and the hook.
      
        
        
      
        
      
        
      Tool fingerprinting
      
        
      Pins the exact set of tools a server offers. If a description changes or a new tool appears after you approved it, calls are blocked until you review and re-approve. The proxy can also hide changed tools from the agent.
      
        
      Limit: a fingerprint proves the description did not change, not that the server is honest. Scan only starts servers you already allowed.
      
        
        
      
        
      
        
      Prompt-injection tripwire
      
        
      Reads what web pages, files and tools send back. If it looks like instructions aimed at the model, that session loses network, credential, persistence and write-type MCP actions until you release it.
      
        
      Limit: a heuristic. It misses some attacks and flags some harmless text. In Hermes the after-call hook only observes, so blocking starts with the next call.
      
        
        
      
        
      
        
      Cost per shipped result
      
        
      cephalo cost adds up what your Claude Code and Hermes sessions cost and divides it by the pull requests that were merged with passing CI. It also shows how much went on work that did not ship.
      
        
      Limit: Claude Code dollars are an estimate (token counts times Anthropic’s list prices), not what a subscription charged you. A session is linked to a PR by its branch name, and Hermes often records none. Needs a logged-in gh.
      
        
      
        
      
        
      Dashboard
      
        
      cephalo dashboard writes one HTML file: overview, sessions and cost, and what the seatbelt blocked. --team shows every developer’s published log together. Nothing is hosted and the page makes no network requests.
      
        
      Limit: a file you generate and open yourself, not a hosted service, and only as fresh as the last time you generated it.
      
        
      
        
      
        
      Shared policy and audit sync
      
        
      cephalo sync shares your rules and audit log through a folder you already have: a synced drive, a network share, or a git clone. Pulling shows what would be added, changed or removed, asks, and backs up first. Every developer’s log lands in one folder, with user and time.
      
        
      Limit: a hash shows the file arrived intact, not who wrote it, so anyone who can write to the folder can publish a policy. Nothing syncs by itself; each developer runs pull.
      
        
      
        
      
        
      Signed policy bundles
      
        
      cephalo sync keygen makes an Ed25519 key pair for whoever publishes policy, and cephalo sync push then signs it. Each developer runs cephalo sync trust on the public key once; after that cephalo sync pull refuses policy that is unsigned, signed by another key, or changed after signing. It uses Node’s own crypto and local files; nothing is sent anywhere.
      
        
      Limit: it proves who published a file, not that the rules are good. The public key has to reach developers by a route other than the shared folder, and there is no key rotation or revocation beyond editing the trust file. Not yet tried on macOS or Linux machines.
      
        
      
        
      
        
      Local-model judge
      
        
      Optional and off by default. A small model running in your own Ollama looks only at commands that show a risk signal and that the rules allow. It can block or ask you; it can never lift a rule’s block. If the model is down, slow or confused, Claude Code asks you instead of letting the command through. Nothing leaves the laptop. cephalo models eval scores it on 128 labelled cases.
      
        
      Limit: on our own set it caught 37 of 38 risky commands but also stopped or asked about 17 of 73 safe ones, and a model call takes about 3 seconds on a CPU. Hermes, Codex and Cursor cannot be asked, so there an unsure answer is logged and allowed. It is a second opinion, not a guarantee.
      
        
      
        
      
        
      Secrets vault
      
        
      Store a token once. The agent uses it through cephalo run and never sees the value: output is scrubbed, including base64 and URL-encoded copies. Each secret lists the commands it may be used with.
      
        
      Limit: hooks, not a sandbox. An agent running as you could still go around it; real isolation needs another OS user or a container. Windows DPAPI is tested; the macOS Keychain and Linux Secret Service backends have not run on real machines.
      
        
        
      
        
      
        
      Incident to rule
      
        
      Pick something an agent did. Get narrow, balanced and broad rule options, each tested against your own history and against patterns that could hang the hook. Confirm to add it, with a backup and an undo.
      
        
      Limit: rules match text, so a rephrased command can still get through. “Would have blocked 0” only speaks for your own log.
      
        
        
      
        
      
        
      PR replay and replay bundle
      
        
      A replay of what the agents did on a branch: counts, a needs-attention list, files written. As PR comment text, an interactive HTML file, or JSON. --format bundle makes one shareable file with the replay, what its sessions cost, and whether the branch shipped. Posting to a PR needs --comment and a confirmation, using your own GitHub login.
      
        
      Limit: a record from a local log, not a signed attestation. Agents are blocked from editing the log, but anything running as you could. The posting path has only run against a stand-in for gh. A bundle shows every command in its window, so read it before you send it.

      Honest limits
      
      
      A seatbelt, not a sandbox.
      
      
      What Cephalo does, and the matching thing it does not do. Everything here comes from how the code behaves today.
      
    
      
    
      
      
      
        What Cephalo does and does not do
        
      Cephalo doesCephalo does not
      
        
          
      +Check every shell command and file path an agent asks to use, before it runs, against your rules. First match wins.
              −Understand what a script does once it runs. It matches text patterns, so a command assembled at runtime, or hidden inside a script file, can slip past.
      
          
      +Clean up common disguises such as r''m, carets, backticks and .. in paths, and check both the raw and the cleaned text.
              −Catch every trick. Cleaning removes the common ones, not all of them.
      
          
      +Add one line per decision to a local audit log, and block agents from writing that log or your rules file.
              −Make that log tamper-proof. Those protections are rules: you, or anything running outside the hooks, can still edit the files, so the log is a record and not a signed proof.
      
          
      +Allow the call and log the error if the hook crashes or gets invalid JSON, so a broken guard never freezes your agent.

      Questions
      
      
      Short answers.
      
    
      
    
      
      
      Does anything leave my machine?
        
      Cephalo does not report usage anywhere: the code has no telemetry or analytics. It makes network calls in only these cases: to MCP servers you have configured, when it scans their tools; to the Ollama address in your config, if you turn a model role on (they are all off by default); and the cost report runs GitHub's gh tool to look up pull-request status. Everything else, including the audit log, stays in ~/.cephalo. This website is separate from the command: it counts page visits with GoatCounter, which sets no cookies, and publishes the totals in the Open numbers section.
      
      
      Does a block hold under --dangerously-skip-permissions?
        
      For Claude Code, yes. Its documentation says a PreToolUse hook that returns a deny blocks the call even in bypassPermissions mode or with --dangerously-skip-permissions, and Cephalo's hook uses exactly that. See the hooks guide. I have not confirmed the same for Hermes, so treat it as unconfirmed there.
      
      
      How do I write a rule?
        
      Add a block to ~/.cephalo/rules.yml with an id, a description, a type (command or path), a pattern (a case-insensitive JavaScript regular expression) and action: block. Rules are checked in file order and the first match wins. Draft one in the builder, then check it with cephalo test "your command".
      
      
      What happens when no rule matches?
        
      The call goes ahead, and one line is still written to the audit log. Cephalo only stops what a rule says to stop.
      
      
      How do I see what was blocked?
        
      cephalo log --blocked lists recent blocks, cephalo watch follows decisions live, cephalo replay summarises a branch for a pull request, and cephalo dashboard writes a local HTML overview.
      
      
      Can the agent turn it off?
        
      Built-in rules stop agents from writing the Claude Code or Hermes config (where the hook lives), Cephalo's rules file, audit log and vault files, and its MCP and tripwire state. They are rules, not a sandbox: you, or anything running outside the hooks, can still edit those files, and a crashed hook lets the call through. See the limits.
      
      
      Does it work on Windows?
        
      Yes. Windows is the platform it has been run on for real. macOS and Linux have adapters that are covered by unit tests only.
      
      
      Will version 0.1.1 stay free?
        
      Yes. Version 0.1.1 is MIT licensed, stays on npm, and stays free and open source. Nothing that is in it moves to a paid plan.
      
      
      What is in Pro and Team?
        
      Pro adds three new features that launch with 0.2.0: a network egress allowlist, a tamper-evident audit log and a bypass benchmark. Team is Pro plus the dashboard, shared policy and audit log sync through a shared folder; the hosted dashboard is Planned. The three Pro features do not exist until they are built, tested and released, and the site marks them as launching Nov 10 until then.
      
      
      What is the CEPHALOG code?
        
      Early users get 20% off the first year of Pro or Team with code CEPHALOG. It works from launch day, Nov 10, 2026. There is no checkout yet.
